# Hasura DDN v3 Engine

This directory contains the Hasura DDN v3 engine configuration and build output.

## Directory Structure

```
engine/
├── Dockerfile.engine     # Dockerfile for building the engine image
├── README.md            # This file
└── build/               # Generated by 'ddn supergraph build local' (DO NOT EDIT)
    ├── auth_config.json
    ├── metadata.json
    ├── open_dd.json
    └── .env.engine
```

## Build Process

### Step 1: Build Supergraph Metadata

Run from the project root:

```bash
ddn supergraph build local
```

This command:
- Compiles all `.hml` metadata files from subgraphs
- Validates the supergraph configuration
- Generates compiled JSON files in `engine/build/`

Output files:
- `auth_config.json` - Authentication configuration
- `metadata.json` - Schema metadata for introspection
- `open_dd.json` - OpenDD specification (main metadata)
- `.env.engine` - Environment variables for connectors

### Step 2: Build Engine Docker Image

```bash
# Build the engine image with compiled metadata
docker build -t hasura-ddn-engine:v1.0.0 -f engine/Dockerfile.engine engine/

# Or use the helper script
./scripts/build-engine.sh v1.0.0
```

### Step 3: Push to Registry

```bash
docker tag hasura-ddn-engine:v1.0.0 your-registry/hasura-ddn-engine:v1.0.0
docker push your-registry/hasura-ddn-engine:v1.0.0
```

## Important Notes

### DO NOT Edit build/ Files

The `engine/build/` directory is **generated by the DDN CLI**. Never manually edit these files.

To make changes:
1. Edit source files (`.hml` files in subgraphs)
2. Run `ddn supergraph build local` to regenerate
3. Rebuild the engine Docker image

### Immutable Builds

Each engine build is immutable and should be tagged with a version. This enables:
- Rollback to previous versions
- Zero-downtime deployments
- A/B testing between metadata versions

### Environment Variables

The engine requires these environment variables:

| Variable | Value | Purpose |
|----------|-------|---------|
| `AUTHN_CONFIG_PATH` | `/md/auth_config.json` | Authentication configuration |
| `METADATA_PATH` | `/md/open_dd.json` | Main metadata (OpenDD) |
| `INTROSPECTION_METADATA_FILE` | `/md/metadata.json` | Schema introspection |
| `ENABLE_CORS` | `true` | CORS support |
| `OTLP_ENDPOINT` | Optional | OpenTelemetry endpoint |

## Deployment to Kubernetes

The engine image is deployed to Kubernetes with the compiled metadata baked in.

Example deployment:

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: hasura-ddn-engine
spec:
  replicas: 3
  template:
    spec:
      containers:
      - name: engine
        image: your-registry/hasura-ddn-engine:v1.0.0
        ports:
        - containerPort: 3000
        env:
        - name: AUTHN_CONFIG_PATH
          value: "/md/auth_config.json"
        - name: METADATA_PATH
          value: "/md/open_dd.json"
        - name: INTROSPECTION_METADATA_FILE
          value: "/md/metadata.json"
        - name: ENABLE_CORS
          value: "true"
```

No ConfigMaps or volume mounts needed - metadata is in the image!

## Troubleshooting

### Build fails with "No such file or directory"

**Problem**: The `build/` directory doesn't exist or is empty.

**Solution**: Run `ddn supergraph build local` first to generate the metadata files.

### Engine fails to start

**Problem**: Missing or invalid metadata files.

**Solution**:
1. Verify all `.hml` files are valid
2. Run `ddn supergraph build local` and check for errors
3. Rebuild the Docker image
4. Check engine logs for specific error messages

### Changes not reflected

**Problem**: Made changes to `.hml` files but engine still serves old schema.

**Solution**: DDN v3 uses immutable builds. You must:
1. Run `ddn supergraph build local` to compile changes
2. Rebuild the Docker image with a **new version tag**
3. Deploy the new image version to Kubernetes
